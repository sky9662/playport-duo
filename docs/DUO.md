# Playport Duo

This community fork retains Playport's app identity, built-in JIT helper, game prefix and save locations. Upgrade an existing installation in place after backing up saves.

Settings > Graphics and each game's options expose Game cursor, DOOM memory compatibility, and OpenGL 4.1 compatibility. Default keeps the installed cursor and shared-image behavior and each title's OpenGL profile. Off explicitly removes the OpenGL version overrides from the launch copy of the shared configuration and the process environment, without editing the shared file; changing mapping or graphics compatibility applies on the next game start. Cursor display still follows the game's cursor visibility request.

Cursor size is adjustable from 100% to 400% in the same settings. Turing Complete defaults to 200%; other games retain 100%. Scaling enlarges the image around its hotspot, so the guest click position stays unchanged. Choose 100% to restore the original presentation.

Smooth cursor scaling uses linear filtering when enlarging the game's original cursor image. Turn it off to retain sharp pixel edges. Filtering does not add detail to a low resolution source image or replace the game's custom cursor shape.

The visible game cursor is confined in Wine to the foreground client's rectangle, intersected with any narrower game clip. This constrains the actual Windows input position rather than drawing an arrow at a different location. Only the clip installed by this feature is restored when the cursor is hidden, host UI is shown or presentation loses focus; a later clip set by the game is left alone. Letterboxing remains supported. This confinement still requires owner validation with a letterboxed game and a game using hidden-cursor mouse look.

The OpenGL 4.1 compatibility row displays Default · On when the game's profile supplies both OpenGL 4.1 and GLSL 410 overrides. These are Mesa version overrides for shader compatibility, not a promise that the renderer implements every OpenGL 4.1 feature. The release UI can explicitly enable or remove them; restart the game to apply a change.

Settings > Controls and each game's options offer independent touch trackpad and mouse sensitivity from 10% to 400%. Mouse sensitivity also controls relative touch look. Absolute tapping, scrolling, controller look and gyro remain separate. A game's Default follows Settings; resetting Settings restores 100%.

The running game's menu (three-finger tap, or hold a controller's Home button) also exposes both sensitivity steppers under Controls, including 250%. Changes are saved for that game and take effect when resuming.

Touch acceleration is On by default in Settings > Controls, each game's controls and the running game's Controls menu. It applies a continuous speed curve to touch trackpad and touch look before sensitivity: 0.5× at up to 60 points/second, rising smoothly to 1.5× at 600 points/second. Slow strokes are finer and fast strokes travel farther; Off restores the original constant multiplier. Each game can override Settings or follow Default. This adds no waiting period, prediction, inertia or movement threshold. It changes the response to delivered coordinates and does not recover movement the touch system has not delivered. Absolute pointing, scrolling, physical mice, controllers and gyro keep their existing behavior.

The layout editor offers Multi-select: tap movable controls to include or exclude them, then drag a selected control or pinch the group's box to move or scale them together. Select all excludes full-screen pointer/look surfaces. Group moves keep spacing at the safe-area boundary, and a completed gesture is one undo step. Single-selection still exposes individual labels and bindings.

Profiles opens three shared, nameable template slots, each containing separate Inner and Outer layouts and preset choices. Save both display layouts stores both drafts, with confirmation before replacing a template. Apply copies both into this game's editor; Done saves the game's independent copies, while Cancel discards game edits from the current editor session. Explicitly saving a shared template is a separate action and is retained. Undo/redo is kept separately for each display and affects the display currently being edited. Editing a game or replacing a shared template never changes another game's existing copy. Earlier single-layout templates load as Outer plus a derived Inner copy.

The visible scene's horizontal size class chooses Inner (regular) or Outer (compact), without rewriting either stored copy. Inner uses its explicit layout when one is saved. Until then, it derives a starting layout from the game's Outer copy or the built-in preset, moving upper-left and upper-right groups to the corresponding side's vertical midpoint while preserving their spacing, sizes and actions. Outer keeps the earlier stored layout and corner placement. The editor labels the current display and can switch previews on the current canvas; folding also switches the active display. Merely opening the editor does not save a custom copy. Sensitivity, opacity and gyro remain game-wide settings. These layout-class transitions still require device validation on both panels.

The aspect ratio and resolution select the Windows virtual desktop. Phone uses the current scene's shape; 4:3 uses an inscribed rectangle and preserves bars rather than stretching. Wine enumerates common 4:3 modes that fit that desktop, including 720x540, 960x720, 1024x768 and 1280x960. Available modes update with scene geometry while the game's current logical mode remains selectable and unchanged until the game changes it. A game's selected display mode and actual presented framebuffer remain distinct from the physical panel. An engine may filter or fix its own modes. This fork does not rewrite Turing Complete's fullscreen or resolution settings.

Duo edge-to-edge behavior requires the genuine iOS 27.1 SDK. Build roots are read from xtool's swift-sdk.json, without renaming SDK directories or spoofing SDK versions. Xcode 27 SDK stubs require a linker supporting arm64e.x1; Apple's ld64 dependency uses the upstream TextAPI fix. Keep previous SDK and toolchain installations available during migration.

The memory page distinguishes the entitlement present in the signature from iOS's estimated current process budget. That estimate can change; physical RAM is not the process limit.

Built-in JIT and the restart after a game discover the RemotePairing port through Bonjour. Only services resolving to this phone's own active interface addresses are eligible; other devices on the network are ignored. Discovery takes at most three seconds and falls back to the previous port 49152 when no unique local port is found. The VPN target stays 10.7.0.1, and existing pairing credentials and the JIT protocol are unchanged. A connected VPN route alone does not establish that the debugging service is reachable. This change still needs device validation before it can be called a fix for a particular phone.

Cloud sync failures show details and a retry action on the game page. Existing saves and the losing side of an explicitly settled conflict retain the existing backup behavior. A failed download is not recorded as successfully synchronized.

Auto-Cloud directory root overrides for Windows are read from each game's PICS `ufs/rootoverrides`. For example, Turing Complete keeps `%SteamCloudDocuments%` in server file names while its Windows override stores those files under `AppData/Roaming/Turing Complete`. Both downloads and local-file discovery use that mapping, retaining the original cloud names for uploads and comparing existing saves before writing. Directory additions are supported; replacement/path-transform overrides remain unsupported rather than guessing a destination. See [Steamworks Auto-Cloud root overrides](https://partner.steamgames.com/doc/features/cloud#root_overrides).

Host tests do not establish device compatibility. Full-screen folding, mode selection inside Windows/OpenGL/Vulkan games, cursor alignment, cloud synchronization and performance require owner validation of the native IPA after an in-place test installation. Distribute the final IPA only after that validation.
